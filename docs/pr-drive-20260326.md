## PR #56 — `docs-cost-routing-policy-2026-03-25-exec` → main

**Mergeable:** Yes (CLEAN)

**Cursor findings:**

### Bug 1 (HIGH) — Regex missing word boundary in `FINANCIAL_PATTERNS`

**File:** `microservices/core/src/application/routing/routingClassifier.ts`

Current second `FINANCIAL_PATTERNS` entry:

```typescript
/(?:owes?|rent|arrears?|balance|invoice|payment)\s+(?:of\s+)?[£$€]?\s?\d/i,
```

Words like `"current"`, `"parent"`, `"different"` all contain `"rent"` as a
substring. Because there is no `\b` before the alternation, a message like
`"the current balance is fine"` matches `rent\s+…` at the `rent` inside
`"current"` and is wrongly classified as `financial-data`, blocking it on
starter/pro tiers.

**Fix — apply to `docs-cost-routing-policy-2026-03-25-exec` branch:**

```diff
-  /(?:owes?|rent|arrears?|balance|invoice|payment)\s+(?:of\s+)?[£$€]?\s?\d/i,
+  /\b(?:owes?|rent|arrears?|balance|invoice|payment)\s+(?:of\s+)?[£$€]?\s?\d/i,
```

Single character addition (`\b` before `(?:`). The word boundary ensures `rent`
only matches when preceded by a non-word character (space, start-of-string, etc.),
eliminating substring false positives.

### Bug 2 (LOW) — `SubscriptionTier` redefined locally

**File:** `microservices/core/src/application/routing/routingTypes.ts`

```typescript
// routingTypes.ts — local copy:
export type SubscriptionTier = "starter" | "pro" | "business" | "developer";

// Canonical source in subscriptionRepository.ts:
export type SubscriptionTier = (typeof subscriptionTierEnum.enumValues)[number];
```

If a tier is added to the DB enum, `routingTypes.ts` won't surface a compile
error. Acceptable tech debt for this PR; file a follow-up to re-export the type
from `subscriptionRepository.ts` (requires confirming no circular dependency).

**Verdict:** Apply the `\b` word-boundary fix before merge. Low-severity type
duplication can be a follow-up.

## PR #58 — `feat/task-events-v1-local-2026-03-25` → main

**Mergeable:** Yes (UNSTABLE = no CI signal, not a real failure)

**Cursor findings:**

### Bug 1 (HIGH) — Fire-and-forget terminal task events (Lambda correctness)

**File:** `microservices/core/src/application/chat/chatHandler.ts` (~L427–467)

Current code uses `.catch()` chained fire-and-forget for `task.completed` and
`task.failed` event writes:

```typescript
// BUGGY — Lambda may freeze before this promise resolves
taskRepo
  .appendEvent({ taskId, eventType: "task.completed", … })
  .catch((err) => console.error("…", err));
```

On AWS Lambda, when the handler returns, the execution environment is frozen.
Unawaited promises that haven't resolved yet are silently dropped. Tasks will
be permanently stuck in the `"running"` state, never reaching a terminal state.
Note that `task.started` is correctly awaited; only the terminal events have
this bug.

**Fix:** The orphan branch `feat/task-events-v1-local-2026-03-25-fix` (commit
`24bfd9e`) already implements the correct pattern:

```typescript
// FIXED — awaited before Lambda can freeze
if (taskId) {
  try {
    await taskRepo.appendEvent({
      taskId,
      eventType: "task.completed",
      source: "chat",
      payload: {},
    });
  } catch (err) {
    console.error("Task completed event failed (non-fatal):", err);
  }
}
```

Same pattern applied to `task.failed`.

### Bug 2 (LOW) — Dead export `emitChatTaskEvents`

`emitChatTaskEvents` is exported from `chatHandler.ts` but never imported or
called anywhere. The inline task-event logic in the handler already covers the
same responsibility. The orphan fix branch also removes this dead export.

**Verdict:** Cherry-pick commit `24bfd9e` from `feat/task-events-v1-local-2026-03-25-fix`
onto `feat/task-events-v1-local-2026-03-25` before merging:

```bash
git checkout feat/task-events-v1-local-2026-03-25
git cherry-pick 24bfd9e
git push origin feat/task-events-v1-local-2026-03-25
```

This incorporates both fixes (awaited terminal events + dead export removal) in
a single clean commit.
